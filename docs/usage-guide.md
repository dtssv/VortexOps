# 使用操作说明

面向 VortexOps 用户的操作手册，从登录入门到各功能实操。配合 [前端设计](frontend.md)（交互细节）与 [API 设计](api.md)（接口）使用。

> 角色说明：**平台管理员**(platform_admin) 管全局；**空间管理员**(admin) 管空间；**开发者**(developer) 构建发布；**测试**(tester) 构建；**访客**(viewer) 只读。下文标注「需要 XX 权限」。

---

## 1. 快速入门（5 分钟跑通第一个应用）

### 1.1 登录与首次引导

1. 用账号登录（本地账号 / OIDC / LDAP，由管理员配置）。
2. 首次登录触发分步导览：工作台 → 空间 → 应用 → 分组 → 构建 → 发布，可随时跳过。
3. 顶部菜单按你的角色动态显示（无权限的菜单不出现）。

### 1.2 最小路径：代码到运行

假设管理员已接入集群与 Jenkins，你作为 developer 要把一个 Java 服务跑起来：

1. **进入空间**：顶部切换或点击空间卡片（需是该空间成员）。
2. **创建应用**：空间详情 →「新建应用」→ 填名称、Git 仓库地址、默认 Registry/Jenkins。
3. **创建分组**：应用详情 →「新建分组」→ 选集群/Namespace → 选资源规格（如 2C4G）→ 提交。
4. **构建镜像**：应用详情 →「新建构建」→ 选分支 → 构建策略 Java → 基础镜像 → 提交，看日志直到成功。
5. **发布**：构建成功后点「发布」→ 选刚构建的镜像 → 整组发布 → 等待 Pod 就绪。
6. **查看运行**：分组详情 → Pod Tab，看到 Running 即成功；可「查看日志」验证。

详细步骤见后续章节。

## 2. 空间与应用管理

### 2.1 创建空间（平台管理员）

系统管理 → 空间 → 新建：名称、显示名、描述、Owner。创建后：
- **绑定集群**：空间详情 → 集群绑定 → 选集群 + 填 Namespace 前缀 + 是否自动建 Namespace + ResourceQuota。
- **添加成员**：空间详情 → 成员 → 添加用户 + 角色（admin/developer/tester/viewer 或自定义）。
- **设置配额**：空间配额（最大应用数、分组数、CPU/内存总量等）。

### 2.2 创建应用（空间 admin/developer）

空间详情 →「新建应用」：
- 名称、显示名、描述、Owner。
- Git 源：选已配置的 Git 凭证 + 仓库地址；或新建 Git 源。
- 默认 Registry、默认 Jenkins（可后续改）。
- 可选图标、标签。

### 2.3 应用成员与角色

应用详情 → 成员 Tab：
- 应用级成员独立于空间成员，可设不同角色。
- 空间 admin 隐式继承应用 admin。

## 3. 分组与资源配置

### 3.1 创建分组

应用详情 →「新建分组」：

1. **基础信息**：名称、环境（dev/test/staging/prod）、集群、Namespace、副本数。
   - **工作负载类型**：
     - `Deployment`（默认，无状态服务）
     - `StatefulSet`（需稳定身份/顺序，如数据库主从、自动启用稳定 IP）
     - `CronJob`（定时任务，填 cron 表达式，带可视化预览如「每天 2:00」）
     - `Job`（一次性任务，填 completions/parallelism）
2. **资源规格**：
   - 「套用模板」一键选预设（如 `标准-4C8G`、`GPU-8C32G+1*A100`），再微调。
   - CPU/内存：设请求值与上限值。
   - 磁盘：临时盘大小 + StorageClass。
   - GPU：卡数 + 型号（仅显示该集群有的型号）；选定后自动配 nodeSelector 与容忍。
   - 右侧实时预览生成的 K8s resources YAML。
3. **网络配置**：
   - 网络模式：ClusterIP（默认）/ NodePort / LoadBalancer / HostNetwork。
   - 端口映射：名称、端口、目标端口、协议。
   - **稳定 IP**（`keepPodIp`）：开启后，重新部署/滚动更新后容器 IP 不变（自动保留，无需填 IP）。适用于需稳定 IP 的场景（白名单、有状态）。
   - **公网访问**（`allowEgressInternet`）：默认关闭（更安全）。
     - 关闭时 Pod 不能访问公网，可配白名单（CIDR 或域名+端口，如镜像仓库、npm registry）。
     - 开启时提示风险，生产需审批。
   - Ingress：开关 + host/path。
   - NetworkPolicy（入流量）：开关，默认仅放行同 Namespace。
4. **调度**（高级）：nodeSelector、节点亲和性、容忍污点、PriorityClass。
5. **策略与弹性**：滚动/重建、maxSurge/maxUnavailable、健康检查、发布需审批；**HPA 弹性伸缩**开关 + min/max + 指标（CPU/内存/自定义）。
6. **确认**：汇总预览 → 提交。

> 资源/网络/弹性变更不即时生效，提交后生成配置版本，需发布才应用（可审计可回滚）。

### 3.2 克隆分组

分组详情 →「克隆分组」：复制规格/配置/配置集绑定到新分组，快速创建相似分组（如 prod 克隆出 staging）。

### 3.3 查看 YAML

分组详情 → YAML Tab：只读展示渲染后的 K8s 工作负载 YAML，便于核对实际下发内容。

### 3.4 弹性伸缩（HPA）

分组详情 → 弹性伸缩 Tab：
- 开关 HPA，设 min/max 副本。
- 指标：CPU 利用率（如 >70% 扩）、内存利用率、自定义指标（需集群装 Prometheus Adapter，如 QPS）。
- 查看实时副本数曲线与伸缩事件。
- HPA 到顶（已达 max 仍高负载）会告警。

## 4. 代码与构建

### 4.1 配置 Git 源

应用详情 → Git 源 Tab：
- 选 Provider（GitHub/GitLab/Gitea/通用），填仓库地址 + 凭证。
- 测试连接成功后，分支/Tag 可异步加载。
- 可配置 Webhook 自动构建：推送某分支即触发构建（见 §4.4）。

### 4.2 新建构建

应用详情 →「新建构建」：
1. **代码来源**：选 Git 源 → 选分支/Tag/Commit（展示最近 Commit）。「从构建模板创建」可一键填充。
2. **构建配置**：
   - 构建策略：Java / Python / Go / Node / 自定义（自定义时填 shell 命令）。
   - 基础镜像：按 runtime 选（如 `java17`、`python3.11`）。
   - Dockerfile 来源：模板（按策略自动生成）/ 自定义（Monaco 编辑器）。
   - contextPath、buildArgs。
3. **镜像目标**：Registry、Repository（默认 `{workspace}/{app}`）、Tag（留空自动生成如 `main-abc1234-20260620-1`）。
4. **确认** → 跳转构建详情，实时日志。

### 4.3 构建详情

- 状态卡片：状态、耗时、Commit、产出镜像（成功可点「发布」）。
- 步骤时间线：checkout / package / build_image / push / callback。
- 日志：终端风格、自动滚动、搜索、下载、断线重连。
- 失败：「相同参数重试」。

### 4.4 Webhook 自动构建

应用详情 → Git 源 → Webhook 配置：
- 填 Webhook URL（平台提供）到 Git 仓库设置。
- 配置触发规则：分支匹配（如 `main`）、事件（push/tag）。
- 触发后自动新建构建，可在构建中心查看。

### 4.5 构建模板

空间/应用级构建模板：把常用构建参数存模板，新建构建时「从模板创建」复用。

### 4.6 构建中心（跨空间）

顶部「构建中心」：所有空间的构建列表，按状态/时间筛选，便于 oncall 排查失败构建。

## 5. 制品版本与回退

### 5.1 查看制品版本

应用/分组详情 → 制品版本 Tab：
- 列表：版本号、tag、digest、git commit、来源构建、扫描状态、使用分组、是否别名、是否曾被回退。
- 行操作：回退到该版本、查看构建详情。

### 5.2 版本别名

为版本打别名（如 `stable`、`production`、`canary`），别名可在版本间移动；回退也可「回退到某别名当前指向的版本」。

### 5.3 回退到指定制品版本

1. 制品版本列表 → 选目标版本 →「回退到该版本」。
2. 发布向导展示「当前版本 → 目标版本」差异（commit、tag、digest），以 digest 为准确保精确。
3. 可选同时改配置版本。
4. 走与正常发布一致的滚动/审批流程。
5. 记录 `previous_image_id`，可再次回退（来回切换）。

### 5.4 制品保留策略

应用设置：保留最近 N 个制品版本（默认 50）。被别名引用/近期被回退的受保护，不可清理。

## 6. 配置管理

### 6.1 新建配置版本

分组详情 → 配置 Tab →「新建版本」：
- **文件配置**：表格行（路径、权限、是否 Secret），点编辑弹 Monaco（按扩展名高亮）；支持上传文件。
- **命令参数**：command/args（数组可视化）、env 键值对（可标记 Secret）、envFrom 引用。
- 变更说明 → 保存为草稿。

### 6.2 应用配置

配置版本 →「应用此配置」→ 触发 `config_only` 发布 → 跳转发布详情观察。
> 纯配置变更也是一次 release，可审计可回滚。

### 6.3 配置版本比对

配置 Tab →「版本对比」：选两个版本 → DiffViewer：
- 文件级：新增/删除/修改，文件内容行级 diff（Monaco diff editor）。
- 命令参数/env 差异表格。
- 资源/网络段差异。
- Secret 字段仅显示「是否变更」，不显示明文。

### 6.4 跨分组配置比对

配置 Tab →「跨分组比对」：选两个分组 → 比对各自当前生效配置（或指定版本）：
- 用于排查「同应用 A 分组正常 B 异常」的配置差异。
- 展示文件/env/资源/配置集差异。
- 可「复制某分组配置到另一分组」（生成草稿，需再发布）。

### 6.5 配置回退

配置版本列表 → 选历史版本 →「回滚到此版本」→ 触发 rollback release。不改镜像（沿用当前制品版本）。

### 6.6 配置集（ConfigSet，多分组共享）

**场景**：多个分组共用同一份日志配置、数据库连接、证书、限流规则。

1. **创建配置集**：空间详情 → 配置集 → 新建（名称、scope、合并策略 overlay/prepend/append）。
2. **编辑版本**：配置集详情 → 新建版本（结构同分组配置），设为 current。
3. **关联分组**：分组详情 → 配置集 Tab →「关联配置集」→ 选配置集、设优先级、是否锁定版本（pinned）。
   - `pinned=true`：锁特定版本，不随配置集升级而变（生产稳定）。
   - `pinned=false`：跟随 current，配置集升级后下次发布自动采用。
4. **生效**：发布时平台按 priority 合并各配置集版本 + 分组自身配置（自身优先级最高），结果记入 release。
5. **影响面**：配置集升级时展示「将影响哪些关联分组」。
6. **配置集版本比对**：配置集版本间比对，或与分组配置比对。

## 7. 发布

### 7.1 整组发布（Rolling）

分组详情 →「发布」→ 整组：
- 「套用预设」一键填常用参数。
- 选镜像（制品版本，CVE 准入不通过会置灰并提示）。
- 选配置版本（默认当前；展示关联配置集是否将变更）。
- 变更说明。
- 提交 → 跳转发布详情，实时事件流。

### 7.2 灰度发布（Canary）

分组详情 →「发布」→ 灰度：
- 填灰度 Pod 数或比例（提示「最大 N」）。
- 提交后创建独立 Canary Deployment，少量 Pod 跑新版本。
- 验证后「提升为整组」（新版本滚动到全组）或「放弃灰度」（删 Canary，回到原版本）。

### 7.3 批量发布

选多个分组 + 同一镜像/配置 → 批量发布总览页：
- 每组一行（分组、当前版本、目标版本、状态、进度）。
- 串行（一组成功再发下一组）/并行切换；`stopOnFailure` 失败是否停止后续。

### 7.4 发布预设

把常用发布参数（灰度比例、滚动策略、超时、是否审批、通知通道）存预设，发布时一键套用。预设按 platform/workspace/application 三级。

### 7.5 发布保护

- 生产分组（prod）默认 `release_requires_approval`，需审批。
- 发布窗口：生产发布限制在指定时间段（如工作日 10:00-18:00），窗口外需 admin 强制 + 审计。
- 变更冻结期：大促等期间冻结生产发布。
- 健康检查门控：新 Pod 健康检查失败自动暂停并告警。
- 镜像 CVE 准入：按环境配策略（prod=block_critical）。

### 7.6 发布详情

- 状态卡片 + 进度条。
- 事件时间线（patched/pod_ready/pod_failed...）。
- 关联 Pod 状态变化。
- 操作（按状态/权限）：灰度提升/放弃、终止、回滚到此版本。
- 评论 Tab：团队讨论，@mention。

### 7.7 发布中心（跨空间）

顶部「发布中心」：所有空间发布列表、状态筛选、发布日历视图。

## 8. 中间件管理

### 8.1 部署中间件

空间详情 → 中间件 →「新建」：
1. 选类型（MySQL/Redis/Kafka/ES 等，来自目录）。
2. 填实例名、环境、集群、Namespace、版本、架构（standalone/replication/cluster）、副本数。
3. 参数表单（按类型 schema 动态渲染，如 root 密码、存储大小、StorageClass）。
4. 是否启用备份、变更是否需审批。
5. 提交 → 安装（Helm/Operator）→ 观察就绪 → running。

### 8.2 中间件变更

中间件详情 → 操作：
- 升级版本、扩缩容、参数变更（生成新参数版本 → 应用 → config_only release）、回滚。
- 生产中间件变更默认需审批，升级前可配自动备份。

### 8.3 备份与恢复

中间件详情 → 备份 Tab：
- 手动备份 / 备份策略（定时 Cron + 保留份数）。
- 备份方式：卷快照（最快）、pg_dump/mysqldump、Velero。
- 恢复：恢复到新实例或覆盖现有（生产覆盖需审批）。

### 8.4 应用与中间件连接

记录「哪个分组用了哪个中间件」+ 连接凭证：
- 分组配置可引用连接凭证（envFrom/secretRef）。
- 拓扑视图：应用↔中间件依赖图。
- 影响面分析：中间件故障/升级时反查受影响应用。

## 9. CI/CD 流水线

CI/CD 流水线把「构建→测试→扫描→镜像→部署→验证→晋升」编排起来，实现从代码提交到多环境发布的自动化。详细设计见 [构建与发布 §14](build-release.md#14-cicd-流水线)。

### 9.1 创建流水线

1. 进入「CI/CD → 流水线 → 新建」。
2. 填名称、作用域（空间/应用）、触发方式（手动/Webhook/定时/上游晋升）。
3. 可视化编排阶段（拖拽）：
   - `build`：选构建模板/参数
   - `test`：填测试命令或 Job 镜像
   - `scan`：选代码扫描器 + 镜像扫描策略
   - `image`：构建推送镜像
   - `deploy`：选目标分组/环境
   - `verify`：填冒烟测试端点或 Job
   - `promote`：触发环境晋升
4. 每阶段配门禁（测试通过率、CVE 数、覆盖率、人工审批）与失败策略。
5. 保存启用。

### 9.2 触发与查看执行

- **手动**：流水线页「触发」，填 ref（分支/Tag）。
- **Webhook**：Git push/tag 自动触发（按 `trigger_config.branchMatch` 过滤）。
- **执行详情**：泳道图展示各阶段状态、耗时、门禁结果；点阶段看日志流；人工门禁阶段点「通过/拒绝」。
- **重试/取消**：失败阶段可重试；进行中可取消。

### 9.3 环境晋升（dev → staging → prod）

1. 在 dev 环境验证通过的制品，进「CI/CD → 环境晋升 → 发起」。
2. 选源环境、目标环境、制品版本、目标分组。
3. 选策略：auto（自动滚动）/ canary（灰度晋升）/ manual（人工发布）。
4. 若 `auto_promote_on_verify`，部署后自动跑验证，通过才完成；失败自动回滚。
5. prod 晋升默认需审批，审批通过后执行。

### 9.4 制品签名与 SBOM

- 构建后自动用 cosign/notation 签名，镜像详情可查签名状态与 SBOM。
- 部署门禁可设「生产强制验签」，未签名/验签失败阻断。

### 9.5 CI/CD 看板

- 「CI/CD → 看板」：成功率、MTTR、DORA 指标、阶段耗时分布、失败原因聚类。
- 用于发现交付瓶颈（如测试阶段过慢）与提升交付稳定性。

## 10. 大模型部署

部署大模型（LLM/多模态）推理服务。详细设计见 [大模型部署](model-serving.md)。

### 10.1 接入模型仓库与添加模型

1. 平台管理员在「系统管理 → 模型仓库」接入来源（HuggingFace/OSS/S3/自定义），填凭证。
2. 在空间「大模型 → 模型 → 新建」：填名称、modality（text/multimodal/embedding）、framework（vllm/tgi/triton...）。
3. 添加版本：填来源引用（如 HF repo@rev）、量化、精度、参数量；平台下载权重到对象存储，下载完成状态 ready。
4. （可选）上传 LoRA 适配器到模型，挂载到基座。

### 10.2 部署推理服务

1. 「大模型 → 推理服务 → 新建」。
2. 选模型 + 版本 + 推理框架（按框架动态渲染参数表单）。
3. 选集群、副本数、GPU 卡数 + 型号（校验 TP×PP=卡数）、张量/流水线并行度。
4. 填框架参数（如 vLLM `max_model_len`、`gpu_memory_utilization`）。
5. 配自动伸缩（QPS/队列阈值、min/max）、API Key 开关、审批开关。
6. 预览 GPU/显存占用与 K8s YAML，提交部署。
7. 平台拉权重 → 起推理 Pod → 加载模型 → 健康检查通过 → running，生成 endpoint_url。

### 10.3 调用推理服务

1. 推理服务详情 → API Key → 签发 Key（设限流/配额）。
2. 用 OpenAI 兼容 SDK 调用：
   ```python
   from openai import OpenAI
   client = OpenAI(base_url="{endpoint_url}/v1", api_key="{your_key}")
   resp = client.chat.completions.create(
       model="{model_name}",
       messages=[{"role":"user","content":"你好"}]
   )
   ```
3. 用量在服务详情「用量」Tab 查看（按 Key/调用方统计 Token）。

### 10.4 切模型与回滚

- **切模型**：服务详情 → 切模型 → 选目标版本 + 策略（rolling/blue_green/canary）。
  - 大模型权重加载慢，推荐蓝绿：起绿组验证后切流量，零停机。
- **回滚**：变更历史 → 选历史 release → 回滚（权重+配置一起回滚）。
- **扩缩容**：改副本数（增减 GPU），或配 HPA 自动伸缩。

### 10.5 推理监控

- 服务详情「监控」Tab：吞吐（tokens/s）、延迟（TTFT/P99）、队列、显存、GPU 利用率。
- 内置告警：服务不可用、错误率突升、延迟突增、显存接近上限、HPA 到顶。
- 显存 >95% 时考虑降量化（切 int4 版本）或加 GPU。

### 10.6 常见场景

- **省显存**：基座 72B bf16 需 4 卡 A100；切 int4 量化版本 2 卡即可，成本大降。
- **多租户**：基座 8B 部署 1 卡，挂多个 LoRA 适配器，按请求选适配器，共享基座。
- **A/B 测试**：用多模型路由组，新旧模型按权重分流对比。

## 17. 常见问题

**Q：提交分组资源变更后为什么没立即生效？**
A：资源/网络/弹性变更生成配置版本，需「应用」或发布才生效（可审计可回滚），避免误操作直接打到生产。

**Q：灰度发布和整组发布区别？**
A：灰度先少量 Pod（独立 Canary Deployment）跑新版本验证，可提升或放弃；整组直接滚动到全组。生产建议先灰度。

**Q：稳定 IP 和固定 IP 区别？**
A：平台只提供「稳定 IP」——勾选后 IP 自动分配并保留，重部署不变，无需手动指定 IP。

**Q：配置集和分组配置冲突怎么办？**
A：按优先级合并：配置集作底座，分组自身配置覆盖同 path/key（自身优先级最高）。可在分组「解析最终配置」查看合并结果。

**Q：exec 进生产 Pod 有什么限制？**
A：需 developer+ 权限，生产 Pod exec 默认需 admin 或审批，全程记审计，可选录屏。

**Q：镜像有 CVE 还能发布吗？**
A：取决于部署策略：dev 可设 off（仅展示）；prod 建议 block_critical（Critical CVE 禁止发布）。特定 CVE 可加白名单（填原因+有效期）。

**Q：发布窗口外能发布吗？**
A：需 admin 强制 + 二次确认 + 审计记录。

**Q：中间件升级失败怎么办？**
A：自动 helm rollback 到上一 revision，状态 failed 记录原因；可手动回滚到历史 release。升级前会自动备份（可配）。

**Q：CI/CD 流水线和单次构建/发布什么关系？**
A：单次构建只到「代码→镜像」，单次发布只到「镜像→运行」。CI/CD 流水线把构建、测试、扫描、镜像、部署、验证、晋升编排起来，实现从代码提交到多环境自动发布。你仍可单独用构建/发布，流水线是更高层编排。

**Q：环境晋升到 prod 一定要审批吗？**
A：默认要审批（`approval_instance_id`），可在流水线/晋升配置调整。dev→staging 通常自动，staging→prod 人工门禁。

**Q：大模型为什么切模型用蓝绿而不用滚动？**
A：大模型权重加载耗时长（72B 需 5-10min），滚动会让新旧副本长时间并存且半就绪，影响可用性。蓝绿先起绿组加载完验证再切流量，零停机。

**Q：大模型显存不够怎么办？**
A：① 切量化版本（int4/awq/gptq 显存大降）② 加 GPU 卡数（提高张量并行度）③ 缩短 max_model_len ④ 用 LoRA 适配器复用基座而非部署多份。

**Q：推理服务怎么计量收费？**
A：网关层记录每次请求的 prompt/completion tokens，按 API Key/调用方/服务统计，可设每日 Token 配额与每分钟限流，超限返回 429。

**Q：平台需要单独部署 etcd 或 ZooKeeper 吗？**
A：不需要。业务元数据存 PostgreSQL，Pod 运行态缓存存 Redis，Leader 选举用 K8s 原生 Lease。详见 [架构设计 §5](architecture.md#5-元数据与协调存储决策)。

**Q：我们团队规模小，该选哪种部署方案？**
A：参考 [部署文档 §2](deployment.md#2-规模分级与选型)：**S 规模**（<500 应用、1-5 集群）用单 PG + 单 Redis + MinIO 即可；随业务增长渐进升级到 M/L/XL，无需改代码。

**Q：Pod 的实际运行状态存在数据库里吗？**
A：不存。Pod 是高频变更的运行态，平台用 Redis 缓存（来自 K8s Informer），不入 PostgreSQL。分组「期望副本数」在 DB，「实际就绪数」在 Redis。稳定 IP 分配是例外，写入 `vo_cluster_ip_allocations` 表。
